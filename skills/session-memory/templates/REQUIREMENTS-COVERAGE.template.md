# 需求覆盖矩阵（Requirement Coverage Matrix）

> 用途：证明每条**用户原话/验收/补充/更正**都有原子落点；防止“把助手进度当验收”和“粗 R 行吞掉子要求”。
> 每个原子要求一行；**没有 disposition = 漏**。

## 1. 元信息

| 项 | 值 |
|---|---|
| 会话/日期范围 | `<YYYY-MM-DD ~ YYYY-MM-DD>` |
| 原始 transcript | `<path>` |
| 断点 seq | `<N>` |
| 最后更新 | `<YYYY-MM-DD HH:MM:SS>` |

## 2. 覆盖矩阵

| ID | 用户原话/时间 | 原子要求（一条一个可验收行为） | 设计/实现 | 独立证据（文件:行号 / 测试 / API / UI） | 状态 |
|---|---|---|---|---|---|
| U-001 | `<原话>` `[MM-DD HH:MM:SS]` | `<动词 + 对象 + 可观察结果>` | `<设计/实现位置>` | `<证据>` | ✅/🔄/⬜/⛔/明确不做 |
| U-002 | | | | | |

状态口径：

- `✅`：证据可核查，且验收的是**语义行为**，不是只有字段/标签存在；
- `🔄`：部分完成；必须写清缺哪一条子行为；
- `⬜`：未开始；
- `⛔`：外部阻塞；
- `明确不做`：用户已裁定不做，必须引用原话/时间。

## 3. 双向核对（必填）

| 检查 | 结果 |
|---|---|
| 每条 USER 发言都已原子化 | ✅/❌ |
| 助手承诺/选项/定稿口径已反向核对 | ✅/❌ |
| 是否存在“助手说完成但无独立证据” | ✅/❌ |
| 是否存在一个 R/V 行吞掉多个子要求 | ✅/❌ |
| 每个未完成项都有下一步/证据 | ✅/❌ |

## 4. 独立证据检查

- [ ] 流程图：验证**边关系**（分支/汇合/回边/跳转/finish），不是数 `.class`
- [ ] UI：实际点击控件并观察行为/截图
- [ ] API：实际调用成功与失败路径
- [ ] DSL/资产：端到端运行或回放
- [ ] 没有用助手进度汇报、版本摘要、映射表当证据
