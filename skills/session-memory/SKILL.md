# 会话记忆整理与持续维护（session-memory）

## ★ 这个 skill 解决什么问题

**长对话（几百轮 / 几天）会超出上下文**：模型凭记忆总结 ⇒ 漏读、混入过时说法、
把已被推翻的结论当成现行。本 skill 用**三份磁盘文件**把记忆外置，
并强制**可核查**。

| 文件 | 作用 |
|---|---|
| `docs/DESIGN-SPEC.md` | ★ **主体**：这个软件**应该是怎样的**（后端/前端/数据结构） |
| `docs/DESIGN-SPEC-PROGRESS.md` | ★ **覆盖台账**：47 段（每 2h）读到哪了 |
| `docs/SESSION-INDEX.md` | ★ **分类索引**：每条对话的**标签**（多标签交集）+ 处置状态 |

## ★★★ 配置（★ 通用化的唯一入口 —— 换项目只改这里，**不改本文件、不改脚本**）

> ★ 上表和下文的 `docs/DESIGN-SPEC.md` 之类**全都是【默认值】**。

**覆盖方式（三选一，优先级从高到低）：**

| 方式 | 怎么写 | 适合 |
|---|---|---|
| **命令行** | `--config <cfg.json>` · `--tags <tags.json>` | 一次性 / 多项目并存 |
| ★ **配置文件**（推荐） | 当前目录放 `session-memory.config.json` | 一个项目固定一套 |
| **环境变量** | `SESSION_MEMORY_SPEC` 等（键名大写） | CI / 临时覆盖 |

**可配的键（全部可选；不写就用默认值）：**

| 键 | 默认值 | 含义 |
|---|---|---|
| `docs_dir` | `docs` | 文档放在哪个目录 |
| `spec` | `DESIGN-SPEC.md` | 主体规格书名 |
| `progress` | `DESIGN-SPEC-PROGRESS.md` | 覆盖台账名 |
| `index` | `SESSION-INDEX.md` | 分类索引名 |
| `ledger` | `PENDING-LEDGER.md` | 未完成台账名 |
| `input` | `_both.txt` | `extract.py` 导出的对话文本（`seg.ps1` 会读它） |
| `tags` | （空 = 用内置表） | 分类关键词表 JSON：`{"标签": ["关键词", …], …}` |

```json
// session-memory.config.json 示例
{ "docs_dir": "docs", "spec": "MY-SPEC.md", "index": "IDX.md", "input": "conv.txt" }
```

★ **默认值 = 本技能的历史默认** ⇒ ★ **老项目零配置，行为一个字不变**。

## ★★ 六条铁律（违反即返工）

1. **用户的话 = 规格**，不是建议。★ 不许降级成"打补丁"。
2. ★★ **必须读【双向】**：只看用户的话 ⇒ 漏掉"我提了什么选项、用户裁的是哪个"。
3. ★★ **禁止用"首行预览 / Select -First N 截断"当读过** —— 必须读正文。
4. ★★ **边读边写**（防上下文压缩丢失）；不攒到最后。
5. ★★ **动手改代码前必须先出"设计 vs 现状"对照**（符合 ✅ / 不符 ❌ + `文件:行号`），不符项**先报告等方向**。
6. ★★ **同一段逻辑出现【第三遍】必须抽成函数**（DRY-3，★ 用户 [10-22] 定）
   · **判据**：★ **同一段逻辑**（不是"看着像"，而是"**改一处必须同步改其余处**"）出现 **≥3 次** ⇒ ★ 抽成函数/结构，★ 并在回复里写明"抽到了哪个文件:函数"
   · ★★ **抽完自查**：★ 若抽出的函数**只有 1~2 处调用** ⇒ ★ **说明抽早了**，★ 应内联回去（★ **三处才抽，抽了就要 ≥3 处用**）
   · ★★ **反例（不许抽）**：① ★ 测试里**刻意并列**的用例（★ 独立才好看懂）② ★ 只是**字面前缀相同**的两段 ③ ★ 会**朝不同方向演化**的逻辑 —— ★ **错误抽象比重复更贵**
   · ★ **写之前先搜**：★ "这段逻辑是不是已经存在" ⇒ ★ **宁可先 grep 再写**（★ 我已在 §4.5 之外因此返工过）

## ★★★ 第 0 步（★ 改代码 / 回答设计问题之前，**必做**）

> ★ 用户 [10-12] 追问："**你现在每次做事时都会看已整理的 design spec 吗**"
> ⇒ ★ 当时**没有强制机制**。★ 本节就是补上它。

**任何"改代码 / 改配置 / 回答设计问题"的任务，第 0 步必须：**

```
① 读 docs/DESIGN-SPEC.md 的【相关小节】（用 grep 定位规则编号）
② ★ 在回复里【贴出你读到的规则】（规则编号 + 原话），★ 作为"已读"的可核查证据
③ 读 §4.5「修复进度」确认该条是否已修 / 是否在队列里
④ 再动手
```

★ **禁止**："我记得规格是…" —— ★ 必须**贴出引用**。
★ 若 SPEC 里**没有**相关规则 ⇒ ★ **先问用户**，★ 不许凭记忆或推断开工。
★ 若 SPEC 与代码**冲突** ⇒ ★ 以 **SPEC 为准**（用户的话 = 规格），
  并把冲突记进 §4（L3 对照）。

## ★★★ 强制 1：**每条回复的常驻区块**

> ★ 用户 [10-12] 指令（原话）：
> > "**1 看 design_spec 文档，并在每次对话时作为常驻区块显式写出：
> >  已看过 design_spec 文档。**"

**规则（★ 每条回复都必须有）：**

```
★ 回复的【最开头】固定一行（原样，不改写）：

📖 已看过 design_spec 文档 · §<相关小节> · 规则 <编号> · 修复进度 <§4.5-N>

★ 若本次与设计无关（纯问答/纯排查）⇒ 写：
📖 已看过 design_spec 文档 · 本次无需引用具体小节

★ 若 SPEC 里没有相关规则 ⇒ ★ 写：
📖 已看过 design_spec 文档 · ★ 未找到相关规则 ⇒ 需你裁定
```

★ **禁止**省略这个区块（★ 它是"我确实读过"的**唯一可核查证据**）。
★ **禁止**只写"已看过"而不写**具体小节/规则编号**（除"无需引用"那种情况）。

## ★★★ 强制 2：**"下一步"必须包含"整理上轮对话"**

> ★ 用户 [10-12] 指令（原话）：
> > "**2 每次会话里说的下一步里，必须包含：整理上一对话，并更新到 design_spec
> >  文档里**（如果没有分歧或者新东西就不用更新，**判断依据是软件本身的设计、
> >  实现是否发生了变化**），并**把预期更新内容列出让用户确认**。"

**规则（★ 每次给"下一步"时）：**

```
① ★ "下一步"清单里【必须】有一项：
   "★ 整理上轮对话 ⇒ 更新 DESIGN-SPEC.md"
② ★ 并【列出预期更新内容】，让用户确认：
   · 新增：哪一节 / 什么规则
   · 修改：哪条被取代（★ 要建分歧块 + 改正文）
   · 无变化：★ 说明"设计/实现未变 ⇒ 无需更新"（★ 也要写出来）
③ ★ 判断依据（用户指定）：
   ★ **软件本身的设计、实现是否发生了变化**
   · 设计变了（新裁定/推翻）⇒ ★ 必更新
   · 实现变了（代码改了/修好了）⇒ ★ 必更新（§4.5 修复进度）
   · 两者都没变（只是问答/排查）⇒ ★ 可以不更新，但要说明理由
```

## ★★★ 强制 3：**每条回复必须贴【未完成台账】**

> ★ 用户 [10-12] 指令（原话）：
> > "**每次对话都要更新一遍未完成的台账，显式放到对话里来。**"
>
> ★ 用户同轮的重要背景：
> > "我总觉得**改调度逻辑这个任务我已经说过四五遍了，但是仍然没有完成**！！
> >  而且我还**以为已经完成了**。"
>
> ★ ⇒ 根因就是**没有"完成定义"**、**没有显式台账** ⇒ ★ 每轮都"以为改完了"。

**规则（★ 每条回复都必须有）：**

```
★ 台账文件：`docs/PENDING-LEDGER.md`（★ **默认名**；可用配置键 `ledger` 覆盖）
★ 每条回复【必须】：
   ① 先【更新】台账文件（状态变了就改）
   ② 并把【台账全表】贴进回复（★ 可用紧凑表格，但每条都要在）
★ 每条【必须有】：★ 编号 · 事项 · 依据(`文件:行号` 或 §) · 状态 · 验证方式
★ 状态只允许：★ ⬜ 未开始 / 🔄 进行中 / ✅ 已完成 / ⛔ 阻塞
★ ★ "已完成"必须有【可核查证据】（测试输出 / 日志 / diff）
   ★ **禁止**凭感觉标完成
```

## ★★★ 强制 4：**逐步法**（★ 用户教我的，别的都失败过）

```
★ 一次只改【1~2 个边界】⇒ ★ 立刻 `analyze` + `test` ⇒ ★ 再做下一步
★ 禁止：一次改多处（★ 出错时分不清哪步坏的 —— 我为此浪费过大量轮次）
★ 若一步失败 ⇒ ★ 立刻回退该步，★ 换更小的步
```

## ★★★ 强制 5：**完成定义**（★ 防"以为完成了"）

```
★ 做任何"多步任务"之前：★ 先列出【完整清单】（带 `文件:行号`）
★ 并写出【完成定义】：★ "全部成立才算完成"的勾选清单
★ 每轮对照勾选清单 ⇒ ★ **没勾完就不许说完成**
```

## ★ 执行循环（每轮）

```
① 报进度：读 DESIGN-SPEC-PROGRESS.md 的"分段覆盖"，找下一个 ⬜ 未读段
② 读该段：用 scripts/seg.ps1 取【完整正文】（不要只取首行）
③ 提取：把"设计点"写进 DESIGN-SPEC.md（文字 + 流程图 + 状态图）
        ★ 每条带 [MM-DD HH:MM:SS] 时间戳 + 用户原话引用
④ 矛盾：同话题前后不一致 ⇒ 建【分歧块】（两边原话 + 时间 + 谁覆盖谁）
⑤ 落盘：更新 PROGRESS（该段 ✅ + 进文档章节）
        更新 SESSION-INDEX（该段各条处置：进文档 / 无设计信息）
⑥ 报覆盖：★ "已读 N/47 段（x%）· 未读 段…" —— 没有这句本轮不算完成
```

## ★ 分类标签（可多标签，不写死）

`调度` · `记录` · `前端` · `环境` · `bug` · `测试` · `文档` · `其他`

★ 一条对话**可以同时属于多个标签**（交集），用于后续"按主题查找"。

## ★★ 文档写法（必须遵守）

### ★★★ 【分歧块】与【正文】的分工（★ 我踩过的坑）

```
★ 【分歧块】= 只记录"谁覆盖谁"（两边原话 + 时间 + 状态）
★ 【正文】  = 必须同步改成【现行口径】
⇒ ★ 只写分歧块、不改正文 ⇒ ★ 正文里留着【已被推翻的旧说法】
   ⇒ ★ 读者看到两份互相矛盾的规则
   ⇒ ★ 用户会问"这个设计怎么没体现在文档里"
```
★ **实操**：裁定被推翻时，**两件事都要做**：
1. 建/更新**分歧块**（记过程）
2. ★ **把正文里所有旧说法改掉**（用 grep 搜关键词，逐处替换）
   —— ★ 复查方式：`grep 旧关键词`，确认剩余命中都在**分歧块/历史**里

```markdown
## X.Y ★★ 小节名（[MM-DD HH:MM:SS] 定型）

> ★★ **用户原话**：
> > "……"

> **[MM-DD HH:MM:SS]** ★ "……"

### 规则
| # | 规则 |
|---|---|
| **XX1** | ★ …… |

### ★★ 分歧块 N：话题
| 时间 | 谁 | 说法 | 状态 |
|---|---|---|---|
| … | 用户 | … | ❌ 已作废 |
| … | 用户 | … | ✅ 现行 |

★ **现行口径（后者覆盖前者）**：……
```

★ **每条规则给编号**（R/W/Z/C/P/B…），便于引用。
★ **用户原话必须逐字**，不改写、不润色。

## ★ 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/_conf.py` | ★ **配置解析**（`session-memory.config.json` / `--config` / 环境变量）—— 别的脚本都 import 它 |
| `scripts/extract.py` | 从 `session.v4.jsonl` 导出**双向**纯文本（USER/ASST + 真实时间戳） |
| `scripts/seg.ps1` | 取**指定时间段**的完整对话（含正文，不止首行）。★ **纯 ASCII**（PS 5.1 读无 BOM 的 UTF-8 会按 GBK 解码 ⇒ 中文字面量会破坏解析） |
| `scripts/index_gen.py` | 生成「分类索引」文档（★ 表名可配；关键词表 `--tags` 可覆盖） |
| `scripts/prog_gen.py` | 生成「覆盖台账」文档（★ 正文引用的文档名走 `_conf`） |

★ 会话导出文件由用户提供（`dsh-session-*.zip` ⇒ 解压得 `session.v4.jsonl`）。
★ **时区**：jsonl 里 `time` 是 **UTC 毫秒**；本机 UTC+8 ⇒ **换算后才是真实时间**。
★ **`seg.ps1` 找输入的顺序**（★ 绝不猜）：`-File` ⇒ 配置的 `input` ⇒ 当前目录 `_both.txt`；都没有就**响亮报错**。

## ★★ 何时用本 skill

* 用户说"**继续**"（在整理对话的上下文里）
* 用户说"**整理/总结对话**""**更新设计文档**""**记忆维护**"
* 用户问"**某件事当时怎么定的**" ⇒ 查 `SESSION-INDEX.md` 按标签定位，再回原文
* 用户指出"**你漏了/你记错了**" ⇒ 立刻回原始对话核对，并**把该条补进分歧块**

## ★ 结束一轮时的话术模板

```
📊 覆盖率报告
★ 已读：段 X~Y / 47 = Z%
★ 未读：段 …（时间范围）
★ 文档：DESIGN-SPEC.md = N KB · M 个分歧块

★★ 本批新增：…
❓ 待用户确认：…
```
